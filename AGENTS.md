# RETROVOX SUB-1 / FM-4 & RETROBEAT D-909

Browser synth studio: two polyphonic synths (subtractive SUB-1, 4-operator FM-4, one per page load via `?synth=sub1|fm`), a drum and 303 bass machine, arpeggiator, Web MIDI, installable PWA. Deployed to GitHub Pages from `main`.

## Principles

- **Native web, no build:** classic scripts in `js/` loaded by `index.html` in dependency order, sharing one global scope; hand-written CSS with custom properties; no frameworks, libraries, bundlers or audio samples.
- **Zero GC audio:** audio nodes are built once per voice or page; notes, knobs and timers only schedule AudioParams.
- **Click-free sound:** parameter changes ramp; the master bus limits and soft-clips.
- **Hardware feel:** 1980s analog hardware look; playing the keys and turning knobs never interrupt each other.
- **English for developers:** identifiers, file and directory names (a domain term in a name is English: `envelope.js`, not `huellkurve.js`), comments (JS, CSS, HTML), test names, commit messages and developer docs (`AGENTS.md`, `docs/`, `.claude/`) are English, so anyone can work on the code. The exception is text the user sees or hears: UI strings in `index.html`, `privacy.html` and `js/` (labels, tooltips, `aria-label`s, the meta description, dialogs, alerts, modals, banners, key caps such as Ö and Ä) keep their language: German prose, English panel labels (SAVE, RANDOM, MATRIX). `README.md` has an English part and the same text in German.

## Workflow

1. **Check** (needs `npm install` once): `npm run check`. Green is one line `CHECK OK: ...` (~36 s); red prints only the failing step. It runs `node --check`, ESLint, the type check (`tsc` with `checkJs` over `js/` and `js/lib/`, and `sw.js` with service worker types via `tsconfig.sw.json`; a new `window.X` export needs a line in `types/globals.d.ts`, state fields carry JSDoc types such as `/** @type {number[]} */`), Prettier (JS only), commit messages (commitlint, `main..HEAD`), html-validate, the unit tests and the layout check (`npm run layout`: both synths at five screen sizes in headless Chromium). In Claude Code the Stop hook runs it at the end of every turn that changed files and the PostToolUse hook formats every edited JS file; the PreToolUse hook (`.claude/hooks/git-guardrails.js`) blocks force push, `reset --hard`, `clean -f`, `branch -D`, checkout/restore of the whole tree, other ways to discard changes (`checkout -f`, `stash drop`) and deleting or moving `main`. Plain `git push` of branches and `main` stays allowed; a blocked command is the user's to run (`! <command>`). CI runs the same plus the pull request's commit messages, Firefox layout, the audio render check and gitleaks; Pages deploys only after it passes.
   - **Audio render** (`npm run render`, ~13 s local, ~5 s CI; not part of `npm run check`, runs in CI; `-- --verbose` prints every measurement): each factory preset of both synths plus INIT plays a chord into an OfflineAudioContext in headless Chromium. Red on peak >= 0.98 (safety clipper ceiling), NaN, silence, or a click at note on/off. Seeded `Math.random`, timers on a virtual clock: runs agree to about 1e-6. A new or changed preset that trips a limit is the finding; limits and their calibration sit in `LIMITS` in `scripts/render-check.js`.
   - **iPad check** (`npm run ipad`, ~13 s; not part of `npm run check` or CI, run it by hand after touch or layout changes; needs `npx playwright install webkit`): both synths at four iPad sizes in headless WebKit with touch. Checks page errors, overflow, touch hardening (`touch-action`, `-webkit-user-select`), multi-touch chords and glissando, key hold plus knob drag plus tab tap, and the Drum Rack. Green is one line `IPAD OK: ...`; `-- --only sub1@1180x734`, `-- --verbose`, `-- --browser chromium`.
2. **Tests** (`test/*.test.js`, `node:test`, `npm test` for full TAP output): `test/helpers/load-browser-script.js` loads `js/` files into a `vm` sandbox that doubles as `window`; `createLiveEngine()` (`test/helpers/synth-engine.js`) builds the full audio graph on `FakeAudioContext`, so envelopes, LFO routing and FX are asserted on recorded AudioParam events. Features and behaviour changes need a test; a bugfix starts with a red test.
3. **Look at visual changes:** `npm run capture-screenshots` (add `-- --synth fm` for the FM-4) writes PNGs to `scratch/screenshots/`. `-- --release` overwrites the store screenshots in `screenshots/`, only for a release that changes the look. Manual browser checks: `PORT=3917 node scripts/serve.js` (HTTP; headless Chromium on `file://` skips a script).
4. **Review:** when the check is green, before committing, run the `reviewer` subagent (`.claude/agents/reviewer.md`) on the change and fix its findings. It holds the project's coding guidelines (audio, parameters, UI, tests, release).
5. **Commits:** Conventional Commits with the types of reviewer rule R1 (`feat`, `fix`, `build`, `ci`, `test`, `docs`, `refactor`, `style`, `chore`; `commitlint.config.js`). The check lints `main..HEAD`, CI the commits of a pull request; fix a red message with `git commit --amend` or `git rebase`. No generated changelog: `git log --oneline` is the technical one (release commits carry `(vX.Y.Z)`), the user notes below stay hand-written.
6. **Release:** a commit that changes the app's behaviour (`feat:`/`fix:` in shipped files) bumps the patch version with `npm run bump`; tooling, tests and docs (`build:`, `ci:`, `test:`, `docs:`) bump nothing (all places in `VERSION_LOCATIONS`, `scripts/bump.js`). User-visible changes also get a release note in both parts of `README.md` ("NEW in vX" in English first, "NEU in vX" in German) and a German card in the "Was gibt's Neues" modal in `index.html`.
7. **Merge:** branch, pull request, CI green, then `git merge --ff-only <branch>` on `main` and `git push origin main`. `main` is protected: GitHub takes only a commit whose CI job `check` passed (the pull request's head), no force push, no deletion. A commit made after CI (amend, rebase, merge commit) is rejected with `Required status check "check" is expected`; push it to the pull request's branch so CI runs on it, then fast-forward again.

## Guards that fail the check

`test/synth-params.test.js` and `test/synth-registry.test.js` (parameter table, init preset, knobs and envelope tabs per synth), `test/sub1-mod-matrix.test.js` (matrix definition vs voice), `test/release-consistency.test.js` (version places, script tags vs `PRECACHE_ASSETS`, README NEW/NEU release notes paired), `test/git-guardrails-hook.test.js` (blocked and allowed git commands, hook registered in `.claude/settings.json`), `test/inline-scripts.test.js` (only the service worker registration inline), `test/header-css.test.js` and `test/tab-labels.test.js` (header and tab rules), `.htmlvalidate.json` (HTML structure, unique ids), `scripts/layout-check.js` (layout per synth and screen size), `scripts/render-check.js` (audio of every factory preset, CI).
